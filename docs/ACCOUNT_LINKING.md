# Account linking v1

The user starts this flow in MithrilPF. There is no custom protocol, browser
extension, Microsoft login form, or development authentication bypass.

1. Mod POSTs `/api/v1/auth/challenge` with `version: 1`, lowercase undashed UUID,
   and Minecraft username. Response: `version`, `challenge_id`, `server_id`,
   `expires_in_seconds: 60`.
2. Mod calls Minecraft's Mojang session service `joinServer` with the random
   server ID. Only that service receives the existing Minecraft access token.
3. Mod POSTs `/api/v1/auth/verify` with `challenge_id`. Backend consumes the
   challenge, calls Mojang `hasJoined`, checks UUID, name and deadline, then
   returns `version: 1`, `link_token`, `receipt_token`, `expires_in_seconds: 300`.
4. Mod opens `https://mithril.foo/link#<link_token>`. The fragment is removed with
   replaceState before rendering and is never sent in an HTTP URL. Do not log it.
5. Browser POSTs `/preview` with `token`, shows the verified name, then requires
   explicit confirmation. `/complete` receives `token` and boolean `remember`.
   It consumes the link once, revokes any old cookie session, and issues a new one.
6. GET `/session` returns `{authenticated:false}` or
   `{authenticated:true,user:{uuid,name}}`. POST `/logout` revokes this browser.
   Preview/complete/logout require the exact `https://mithril.foo` Origin.
7. Mod saves `receipt_token` per UUID in its instance, then POSTs `/link-status`
   with `{token: receipt_token}` while its menu is open. This mod-only endpoint
   rejects browser Origin headers and returns `version: 1`, `status: pending`,
   `status: expired`, or `status: linked` plus `user: {uuid,name}`. The mod checks
   that a linked UUID matches its current account. Unknown receipts return expired.

Receipts are separate 32-byte random status-only capabilities, hashed at rest.
They cannot authenticate, complete a link, renew sessions or authorize gameplay.
Before confirmation they expire with the five-minute link. Confirmation associates
them with the issued browser session; renewal extends both, and logout/replacement
revokes both. This uses the existing auth schema (`kind=receipt`), not a migration.
Older clients ignore the additive response field; older servers without it can
still open the browser but do not provide persistent mod confirmation. Polling
does not extend browser session lifetime. Existing users must link once more.

All random tokens contain 32 bytes of entropy (43 URL-safe characters); the
server ID is 39 lowercase hexadecimal characters. Database tokens are SHA-256
hashes. Cookie name/flags and retention are described at `/cookies`. Remembered
sessions expire after 30 days of inactivity, refreshed at most once a day;
non-remembered sessions expire server-side after 24 hours and use a session cookie.
Anonymous browsing does not set a cookie. Confirmation is also a login-CSRF
boundary: never accept a sign-in link generated by someone else.

SQLite is single-process, lock-owned, with expiry cleanup and bounded record counts.
At most four upstream verifications run concurrently. API tests inject synthetic
Mojang responses and temporary storage; there is no runtime bypass switch.
Sessions survive releases, but are not a mod-presence channel or proof of gameplay.

Local development serves anonymous UI normally. Authentication intentionally
requires the production HTTPS origin and Secure cookies; use isolated API tests
for synthetic flows instead of weakening production defaults. Before public
distribution, the owner still needs a full privacy notice, controller/contact
details, and a security reporting channel. This cookie notice is not a legal review.

## Manual acceptance

- Open `/mithrilpf`, choose Link browser using a real licensed account.
- Confirm the correct name, opt into remembering if desired, then enter party finder.
- Reload and restart the browser: remembered identity should persist.
- Reopen the old link: it must be rejected; create another to switch accounts.
- Log out and reload: the old session must no longer work.
- Confirm that the mod changes to Linked as, survives menu/game restart, and
  detects logout. Disconnect networking: cached confirmation must be labelled
  unavailable, not silently deleted. Other Minecraft accounts must not inherit it.
- Cancel the Minecraft screen during verification: no late browser window.
- Test unavailable Mojang/backend and expired links without exposing secrets.

Automated tests are not a substitute for the real Minecraft/Mojang/browser flow.
